# 智能任务调度

Codex 个人插件 `adaptive-task-router`：分析任务目标与验收标准，按不同子任务选择模型和推理等级，使用原生子代理执行、整合并验证。默认先保证质量，再减少不必要的推理、重复执行与返工。

## 使用

安装后在新任务中选择“智能任务调度”插件并发送要求，或使用技能名：

```text
请使用 $route-task 分析并完成下面的任务，按子任务选择合适的模型和推理等级：……
```

只需要方案时：

```text
请使用 $route-task 只分析任务、依赖、选型和验收方案，暂不执行：……
```

只评估是否值得分工时：

```text
请使用 $suggest-task-routing 判断本任务是否值得启用智能任务调度，只给建议：……
```

插件列表中技能可能显示带插件命名空间的名称；通过界面选择对应技能即可。已在运行的任务不保证立即获得新安装的技能，使用新任务是可靠的加载边界。

## 两个入口

| 入口 | 触发 | 行为 |
| --- | --- | --- |
| 智能任务调度 `route-task` | 明确调用或接受当前任务的启用建议 | 展示简明分工，实际执行、必要时升级、最终验收 |
| 智能调度建议 `suggest-task-routing` | Codex 在明显适合分工的复杂任务中自动发现，或用户主动询问 | 仅建议；同意前不开始本插件的调度，拒绝后同一任务不再建议 |

简单任务可由主代理直接完成。复杂任务默认最多同时运行三个子代理，并服从宿主更低的剩余容量。需要足够的原生子代理能力；没有该能力时说明限制并完成主代理能做的工作。

## 能力与边界

- 已实现的技能策略：目标与任务拆分、17 个选项的起始参考、显式配置子代理、依赖和文件责任、失败分类升级、独立复核、真实调用记录。
- 外部依赖：实际模型执行、参数校验、权限、硬并发限制和自动技能发现由 Codex 提供。本插件是技能驱动的调度策略，不是独立调度服务或强制执行引擎。
- 自动建议不保证每个复杂任务都触发；它不是后台监听。无回答不视为同意，也不阻塞原任务中已授权的独立工作。
- 主代理维持当前真实配置；技能不能靠提示词切换已运行的主模型，也不修改全局默认模型、推理等级或额度预算。
- Ultra 作为宿主的委派运行模式单列，不视为 Max 之上的统一能力档。模型可用性随运行环境核对。
- 用量只记录工具提供的事实，不推算订阅扣费；默认不保存跨任务记忆、创建周期监控或使用额外 API 服务。

## 安装与维护

本机安装使用个人市场，命令为 `codex plugin add adaptive-task-router@personal`。源插件与市场条目必须已按[维护说明](docs/MAINTENANCE.md)就位。ZIP 是源码分发包，不是声称 Codex 支持直接导入的安装格式。

插件的源码、配置、参考和文档保持本地版本管理。没有远程代码仓或服务器部署依赖。
