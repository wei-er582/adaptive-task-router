# 智能任务调度 · adaptive-task-router

一个只依赖 Codex 原生子代理能力的个人插件。先定义合格交付，再按难点选择模型与推理等级，必要时递归分派、整合和验证。首次启用后在当前对话持续使用。

## 快速使用

选择插件，或输入：

```text
请使用 $route-task 完成以下任务：……
```

安装后完整技能名称为 `adaptive-task-router:route-task`。未选择插件或需要消除同名歧义时，可输入 `$adaptive-task-router:route-task`；建议入口对应 `$adaptive-task-router:suggest-task-routing`。

启用一次后，后续直接说“继续实现”“再检查这个新问题”等，无需再次勾选。每个新请求仍重新判断范围与验收；简单问答或小修改直接完成，不必开代理。

```text
这次不用插件，直接回答：……
这一步不要委派。
关闭插件，后续按普通方式继续。
重新启用 $route-task，继续：……
完成当前块后先停止。
```

“这次不用”结束后恢复对话内启用；“关闭”持续有效直到重新开启。“停止”保留偏好，但不自动恢复工作，等用户说继续。新对话没有继承有效启用记录时不自动启用；引用别人或旧对话的启用语句不算授权。

只做规划：

```text
请使用 $route-task 只分析任务、选型与验收，暂不执行：……
```

只评估是否值得启用：

```text
请使用 $suggest-task-routing 判断本任务是否值得多模型分工，只给建议：……
```

| 入口 | 启用方式 | 行为 |
| --- | --- | --- |
| route-task | 明确调用或接受建议；当前对话后续持续有效 | 分析、选型、实际分派、按证据交付 |
| suggest-task-routing | 未启用时可自动发现或明确调用 | 只建议；未答不启用，同一任务拒绝后不重复询问 |

已启用后，建议入口不再重复询问。计划模式、单次例外、用户关闭和停止要求始终优先。持续使用通过对话规则及续接状态实现，不修改全局提示，不保证 UI 始终显示已勾选，也不假定宿主会每轮重载技能。

## 实际能力与边界

- 有 17 项可调整选型参考，分别评估求解、验证、全局整合与错误影响；不把表格当实测排行榜。
- 保持主代理的实际配置，逐次指定子代理配置。需要更强判断时先做有价值的专家补位，仍无法验收再建议切换主代理。
- 整棵树共同使用宿主容量与用户限制，没有插件固定三个上限。分支在分配名额内可继续委派，保持最小必要深度。
- 核对共享文件、会话、实验输出及其他资源；条件变化后重验受影响成果。停止时检查后代及本任务进程，恢复前确认版本。
- 技能提供行为指令，宿主提供工具、权限、模型和硬容量。自动发现、实际配置及用量回显受宿主限制。
- 没有原生工具时可单代理完成授权范围；不启动额外 CLI、付费 API 或普通侧边栏任务冒充原生分派。

模型选择以任务质量为准，不推算订阅扣费，不改官方 Ultra 映射、全局模型/推理设置，不启用周期监控。本地维护，不做 GitHub/服务器同步。
