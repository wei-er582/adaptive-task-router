# ADR 0001：原生调度与分离的触发入口

## 背景

用户希望明确调用时自动拆分并执行，普通任务仅在分工明显有益时先询问。当前原生工具能逐个指定子代理模型与推理等级，而默认继承可能复制主代理的昂贵设置。全历史 fork 又不支持模型覆盖。

## 决定

- 将明确执行与自动建议分成两个技能，分别关闭和开启 implicit invocation。建议入口只负责轻量判断与启用选择，不把阅读建议当成执行授权。
- 使用宿主原生子代理，不创建普通侧边栏任务、不加入外部 API 或后台服务。为每项工作传入显式模型、档位和最小上下文，默认 fork 为 none。
- 默认统一管理最多三个子代理，叶子任务不再分派。依赖、共享文件和真实验收由主代理管理。
- 独立保存选型与原生接口参考，主入口只保留跨任务通用策略。选型表是启发式，没有无依据的费用或性能承诺。

## 备选与后果

单一自动执行入口不能准确表达“可建议、先同意再执行”；全局默认配置不能逐任务控制推理投入；独立 API 服务会增加身份、计费和运维边界。因此不采用这些方案。

技能规则并不是强制执行代码，自动发现与实际模型执行由宿主提供，需要用真实行为测试和调用记录验证。插件无法热切换主代理，也不能证明宿主没有回显的底层推理映射。保留这两个限制比给出虚假的强保证更便于使用和维护。
