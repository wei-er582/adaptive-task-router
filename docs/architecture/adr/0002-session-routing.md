# ADR 0002：对话内持续启用与共享容量递归

## 背景

0.1.0 的任务级触发和默认三个叶子代理适合初始验证，但无法表达用户后续要求：一次启用后同一对话持续使用；子代理可在局部发现有收益的分工；容量按宿主动态核算。原生工具不会凭技能文字热切换主代理或证明未回显的配置。

## 决定

保留明确执行与自动建议两个入口。执行入口继续关闭 implicit invocation，已经明确启用的工作规则通过对话和可信续接记录延续。保存路由偏好与工作暂停两个不同状态；单次例外不变成永久关闭，新目标不继承旧目标的业务操作权限。

Root 统一分配共享名额，分支在名额内递归选型；名额含父节点和预留后代，不在每层重置。不设插件固定三个上限和任意层数保证；容量不足时直接做、排队或收束后接续。层级必须对应真实收益，保留独立复核覆盖相同范围的例外。

在原生接口参考中处理配置与调用证据，在协调参考中处理资源、依赖版本和生命周期，在高档参考中分别评估求解、整合和验证。规则按需读取，核心入口不复制全部协议。

## 后果与未采用方案

没有新增调度服务、固定模型角色、全局 AGENTS 规则或长期记忆；因此策略约束不是运行时互斥锁或硬预算。宿主负责权限及硬容量；工具未回显的配置保持未知。单靠 skill 不能保证跨任意上下文丢失仍保留状态，必须验证实际续接并如实标明未测能力。

未采用每层自行使用全部宿主名额、无限转包、默认全 Max、修改 Ultra 映射、每轮要求用户重选插件等方式。安装发现与运行效果独立验收；临时 CLI 仅作为安装入口测试工具，不成为插件正常分派通道。

0.1.0 历史决定保留在 [ADR 0001](0001-native-routing.md)；关于容量、叶子限制和启用作用域以本决策及当前技能为准。
