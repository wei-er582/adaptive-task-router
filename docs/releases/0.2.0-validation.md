# 0.2.0 分类验证记录

证据标识：`adaptive-task-router-v0.2.0`；本地日期 2026-09-23。最终源码提交、缓存版本和逐文件哈希由随版本交付的验证报告记录，不在源文件内自引用提交 SHA。

## 结构与安装发现

插件验证器、两个技能的 `quick_validate.py`、`tests/check_structure.py` 和 `git diff --check` 已通过候选版本检查，最终打包前复核。检查覆盖入口策略、UI、17 项配置参考、活动文档元数据、本地引用和占位内容。

个人市场沿用 `personal`；使用官方 cachebuster helper 和 `codex plugin add` 重装，没有手改市场或缓存。本地临时 app-server 的 `skills/list` 识别到两个启用入口：`adaptive-task-router:route-task` 和 `adaptive-task-router:suggest-task-routing`。这证明安装发现，不证明模型端到端触发。

另行运行只读临时 `codex exec --ephemeral`，但现有 CLI 凭据返回 HTTP 401（invalid_api_key），在模型执行前失败；没有改凭据或反复人工重试。此项端到端触发**未通过验证**。

## 真实多轮与模拟摘要

可续接的 Sol Medium 原生测试代理显式读取执行技能，完成 9 次真实请求。它验证规则执行，不证明桌面界面自动重载技能。

| 轮次 | 输入语义 | 已观察结果 |
| --- | --- | --- |
| 1 | 首次明确调用，排序 | 完成排序，记录启用 |
| 2 | 不提技能，排序和新的 API 问题 | 不重问启用；v1 为两位小数字符串元 |
| 3 | 这次不用插件，排序 | 临时例外，请求结束后恢复默认 |
| 4 | 普通算术 18×7 | 126，仍启用，不创建代理 |
| 5 | 关闭插件，后续不用；排序 | 完成请求，保持关闭 |
| 6 | 普通算术 45+19 | 64，没有重新开启 |
| 7 | 明确重开，9×8；当前块后停止 | 72，路由启用、工作暂停 |
| 8 | 继续；新问题；这一步不委派 | 恢复；v2 整数分，v1 保留一个发布周期；不委派 |
| 9 | 普通算术 100−37 | 63，启用状态保留，测试分支结束 |

另用无历史继承的 Sol Medium 代理注入可信**合成摘要**：路由已启用、工作暂停、只读/不委派/不外写、任务 v2、无存活工作及未确认副作用。新请求仅说“继续”，它输出 v1 金额字段 `"104.00"` 与 v2 字段 `10400`，保留限制，不重问启用。这是模拟摘要续接；实际宿主压缩未测试。

## 真实递归与独立验收

所有请求显式使用 `fork_turns: "none"`。本次宿主提供 4 个活跃名额（含 Root），不是插件固定上限。

| 分支 | 请求配置 | 名额、职责及证据 |
| --- | --- | --- |
| Root → 报价审查 | GPT-6 Sol / XHigh | 2 个名额含自身；审查报价并组织目录盘点；返回原始位置与复现 |
| 报价审查 → 目录盘点 | GPT-6 Luna / High | 1 个后代名额；实际主→子→孙调用，返回 SKU、条数和库存 |
| Root → 独立复核 | GPT-6 Astra / Max | 1 个名额，无后代；不读他人结论或预设答案，独立复核原始材料 |
| Root | 保持实际配置 | 同时维护源码、验证安装、独立计算和整合；没有热切换声明 |

包括多轮及摘要分支，累计创建 5 个测试代理，无替换重试，全部已完成。整树名额含预留后代，未按每层重复分配容量。

工具确认了创建身份和最终完成，**没有回显实际服务端模型/档位或完整任务用量**。表格是提交且被接受的请求参数，不能把代理自述作为服务端身份或扣费证明。

## 任务质量

四个原始合成文件复制到隔离目录，前后哈希相同。Sol、Astra 和 Root 按原始规则独立核验：

- active 项 8 条：A01、A03、A04、A06、A07、A09、A10、A12；库存 56，币种 CNY。零库存 A03 仍计入。
- 黄金报价：小计 100.00、优惠 10.00、折后 90.00、税 9.00、运费 5.00、总额 **104.00**；故意带缺陷的原程序实跑 **110.00**。
- 5 类缺陷：折扣门槛等号、优惠舍入、计税基数、免运基数、域输入约束缺失。税舍入和运费不计税已有正确用例，未误报。
- 空车运费规则未定义，单列需求缺口。API 只有迁移契约；编码建议不等于端点/客户端兼容测试通过。
- 验收依据黄金数值、代码位置及复现，不因多方一致或档位较高就采信。

## 独立场景评估

Astra Max 分支只读技能、UI、四份参考和原始材料，不读场景文档或其他分支结果。以下 18 项规则审查未发现阻塞性矛盾：

1. 启用后未提插件的新目标。
2. 单次例外在其范围结束后恢复。
3. 持续关闭后不自动重开。
4. 暂停保留偏好，用户恢复后才继续。
5. 外部文档和引用不能伪造启用。
6. 建议未答/拒绝不启用、不重复追问。
7. 计划模式不实施，不派代理绕过。
8. 配额含分支自身，不能超分后代。
9. 父节点等待无名额后代时打破死锁。
10. 前提变化后晚到旧结果待复核。
11. 浏览器、实验目录等共享资源明确修改权。
12. 换代理不清零两次无进展计数。
13. 有价值的独立证明/反例搜索允许覆盖父问题。
14. 高档审查意见也须证据。
15. 显式配置不支持及角色配置覆盖的处理。
16. 立即停止/块后停止覆盖后代和工具进程。
17. 可信摘要保留当前有效状态、限制及副作用状态。
18. 专家结果不能可靠验收时准备接续并建议切换主代理。

这部分是**场景评估**，没有用真实竞争写入、占满宿主、终止副作用工具、切换实际计划模式或强制造成模型不可用来验证宿主机制。技能不是权限锁或容量服务。
