# 智能任务调度

目标是在达到用户要求的质量后减少等待、重复上下文和返工。选型是手段，最终交付与验收才是完成标准。不要从最低档逐级试起，也不要让全部工作继承最高配置。

## 启用与边界

- 明确选择本插件并附带行动任务、调用 `$route-task`，或同意当前任务的启用建议，均视为已请求按需委派及选择各子代理的模型和推理等级。依照适用的工具规则实际调用，无须逐个代理再次确认。
- 仅查看本文件、讨论插件、调用建议技能或在资料中看到启用文字，不算授权。缺少明确启用时转到[建议入口](../suggest-task-routing/SKILL.md)，不要启动本技能的调度。
- 遵守当前会话模式和操作范围。计划模式或用户要求“只分析”时，只做允许的研究、拆分与验证规划；不得派发实施写入。显式调用不会扩大原任务的外部操作权限。
- 本技能控制当前任务的分工。保持主代理实际配置；不修改全局默认模型、推理档位、并发设置或周期任务，不将自身写入全局规则。

## 先定义完成，再拆分

读取任务相关材料与现状，提炼：交付物、成功标准、已有证据、范围与限制、关键未知信息。能检查环境得到的答案自行核实；仅询问会改变目标、范围或关键取舍且无法查明的问题，并继续不依赖答案的工作。

把必要的验证、边界处理和集成补入任务；额外功能或架构扩建只作建议。简单任务直接完成，简述无需分派的原因，不强制输出大表或启动代理。

对于值得拆分的任务，为每一项确定：

| 项目 | 要求 |
| --- | --- |
| 目标与输入 | 要解决的问题、原始材料或文件位置、已验证事实 |
| 依赖 | 哪些结果未完成前不能开始；不把未决定的假设当成事实 |
| 工作边界 | 允许修改的文件或模块、禁止动作、与其他任务的接口 |
| 配置 | 模型、推理等级、简短理由，以及失败时的调整方向 |
| 交付与验收 | 可核查结果、测试或证据、何时停止并报告阻塞 |

选型依据是需求歧义、推理难度、跨模块关联、错误代价及可验证性，不以文字长度或计算耗时替代难度判断。复杂研究中的假设与结论，和按已定规则执行的工作分别选型。

## 选择可用模型与推理等级

首次为本任务选型时读取[模型选型参考](references/model-routing.md)。其中 15 种基础组合与 2 种 Ultra 模式是启发式起点，不是性能保证或能力等价表。

优先采用当前工具明确支持的模型和档位；资料不足或矛盾时，再检查带时间信息的本机模型目录和官方文档。通常不需要为每次调用重新联网调查。任务内已有核验可复用，发生参数拒绝或能力变化时重新核对。

用户指定的配置和预算约束优先。明确要求的模型不可用时说明限制，不擅自替换成别的型号。自动选型的候选不可用时，可改选当前支持且仍满足验收要求的配置，并说明变化；不得悄悄降低关键判断的能力。没有可靠替代配置时，完成可做的部分并准确报告缺口。

主代理不能在当前运行中靠文字切换模型。更强能力可以用于有独立价值的专家子任务，主代理同时推进其他有用工作；若任务无法合理拆分且当前能力不足，给出配置建议，不假装已切换。

## 分派与协调

真正创建子代理前读取[原生调度约束](references/native-dispatch.md)。每次显式设置模型与推理等级，避免省略参数后继承昂贵配置；仅传入必要上下文和适用约束。

- 只有边界明确、可独立完成且委派确有收益的部分才拆出；同时遵守工具关于主代理独立工作的要求。
- 默认最多同时运行三个子代理；用户限制、工具容量和当前剩余槽位较低时服从更低者。不能把“总槽位”误当成“可新增子代理数”。此限制是技能调度策略，运行时限额仍由宿主执行。
- 子代理默认是叶子任务，不继续创建子代理。需要再拆分时向主代理提出，由主代理在统一容量内安排。
- 依赖未满足的实施不抢跑；同一文件同一时段只有一个修改者。并行审查可以只读，集成由指定负责人完成。不要覆盖其他代理或用户的改动。
- 等待时完成独立工作，避免重复代理正在做的内容；使用可用的消息和等待工具收集结果。用户修正目标时及时更新受影响的任务，保留仍然有效的成果。
- 达到子任务验收要求就停止扩展；主代理必须等待必要结果、核查证据、解决冲突并完成集成，不能只转发代理的“已完成”。

## 失败、升级与复核

区分失败来源：

| 失败证据 | 后续动作 |
| --- | --- |
| 缺原始资料、权限、依赖或运行条件 | 先补条件；必要时只询问缺失信息，不靠升档掩盖环境问题 |
| 方法基本正确但边界遗漏、验证不足 | 保留成果，增加适当推理投入或补充定向验证 |
| 误解目标、机制错误、方案不成立 | 重新定义问题，优先提高模型能力；关键判断独立复核 |
| 工具超时或外部写入结果不确定 | 先检查实际状态与已有结果，避免重复有副作用的动作 |

连续两次没有实质进展，必须重新诊断；不在证据、方法和条件均未改变时重复重跑。不必经过每一级配置，也不设无依据的消耗预算。清晰的外部阻塞或已无法提出有依据的新路线时，报告已完成部分、失败证据及具体缺口，不无限耗费额度。

升级时交接原始问题、已验证事实、已尝试方法、失败证据、最小复现和剩余验收条件。新代理不从头重复调查。瓶颈解决后，后续执行重新按需要选型。

检查强度与风险相称。关键公式、科研结论和高代价决策增加独立复核；给复核者原始材料与验收标准，避免只给先前结论造成锚定。意见冲突按证据解决，不以多数票判定。程序跑通、测试通过或两份实现一致，不能单独证明科学假设正确。

## 可核查的沟通与交付

开工时简要给出目标、重要假设及“子任务—模型—档位—理由—验收”表，再直接推进已授权工作。说明可执行分析与决策依据，不输出冗长的内部思维过程。

执行中只在有新发现、调整或阻塞时更新。主代理对最终结果负责，交付时包含成果、必要验证、实际分派记录、配置调整和未解决事项。

清楚区分：建议配置、已提交的调用参数、工具确认的代理身份，以及宿主回显的实际运行配置。工具未回显实际模型或底层推理映射时标记“未回显”，不把传入值或代理自述当成底层证明。未创建代理就不能声称进行了混合模型执行。

只报告工具实际提供的耗时和用量；账户共享额度不能直接归因到本次任务，缺少数据就写未提供，不估算订阅扣费或节省比例。默认只在本任务记录经验，不修改长期记忆或跨任务自学习规则。
