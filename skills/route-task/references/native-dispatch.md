# 原生子代理调度

本文件只在准备真正分派时读取。工具名和参数来自当前会话；以下是已验证适用于创建环境的调用方式，不得在不支持的宿主上臆造同名接口。

## 直接调用与上下文

当前环境提供 `collaboration.spawn_agent`，使用该原生工具；其管理工具也直接调用，不放入 `functions.exec`。模型覆盖需要 `fork_turns: "none"` 或工具支持的有限历史；本插件选择 `none` 并手动整理必要上下文，因为全量历史模式不接受模型和推理覆盖。

示例，仅展示调用形状，参数须按真实子任务调整：

```json
{
  "task_name": "extract_verified_facts",
  "model": "gpt-6-luna",
  "reasoning_effort": "high",
  "fork_turns": "none",
  "message": "你负责一个边界明确的子任务。目标：从给定资料提取已发布的接口字段。输入：实际提供的文件绝对路径与相关片段。依赖：无。权限：只读，不修改文件。交付：字段、类型、原文位置和无法确定项。验收：每个字段都有可核对来源，不推测缺失值。不得继续创建子代理；缺少材料或发现工作越界时报告主代理。"
}
```

用真实路径和约束替换示例描述。传递目标、必要原文、相关规则、既有成果、文件责任和停止条件；不要复制整个对话、认证信息或无关工具输出。必须传达尚未确认的假设，不能省略其不确定性。

其他宿主若提供功能等价的原生委派接口，先读取其实际 schema，仅在能明确控制所需配置时使用。参数名称可能不同，不把 `reasoning_effort` 硬塞给不支持它的工具。

## 容量与叶子任务

实际可新增数量取用户限制、默认三个、宿主剩余槽位三者中的最小值。宿主限制若包含主代理，要减去已经占用的主代理及其他活跃代理。分派提示明确“不得继续创建子代理”；确需进一步拆分时交回主代理。

子任务必须能独立推进，且符合工具对主代理同时承担有用工作的要求。不要把同一个完整任务转手给一个代理，再让主代理只等待，以此冒充主模型切换。代理数量不代表质量。

拆分为少量职责清晰的任务；复用同一配置、同一上下文的已存在代理时可使用原生 follow-up。若接口不能改变现有代理模型，升级就创建配置明确的新代理并移交成果，不靠提示其“现在你是另一个模型”。

## 结果与异常

使用当前可用的消息、状态、等待与中断工具。等待时不要反复轮询没有变化的状态，遵守宿主的等待上限并持续处理独立工作。只在确有取消、方向变化或无效重复时中断代理。

收集每个任务的证据位置、变更范围、验证结果和阻塞信息；为有写入的任务检查真实文件与差异，不能仅依据自述。依赖结果达标后才启动下游实施，失败不能被“继续执行”自动掩盖。

没有子代理工具时，继续完成主代理能够完成的授权工作，明确说明采用单代理执行。若缺少指定模型、推理参数或足够槽位，先区分能力不足与暂时容量不足；后者排队或串行处理，不创建普通侧边栏任务或外部 API 调用来绕过限制。

不为普通分派使用 `create_thread`、`send_message_to_thread` 或启动额外 Codex CLI 进程；它们有不同的授权、生命周期和任务可见性。本插件不附带 MCP 服务、API 凭证、后台进程或自动化。

## 调用记录最小字段

每项保留：任务标识、请求模型/档位、工具确认的代理 ID 或任务名、当前状态、证据与验证、调整理由。耗时和用量可选，仅在宿主实际提供时记录。

“请求了 gpt-6-sol/high 并成功创建代理”可以由调用记录证明；“底层实际运行配置”只有宿主回显才能确认，不能靠代理复述模型名验证。未回显时明确记为未回显。也不要从账户级使用百分比差额反推单个代理或本任务成本。
