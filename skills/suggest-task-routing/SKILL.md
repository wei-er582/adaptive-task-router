# 智能调度建议

这是轻量建议入口，不是执行授权。未获同意时，不加载完整选型参考，不启动子代理，不做额外全项目调查，不改变当前任务的执行方式。

## 判断是否值得询问

仅使用当前任务已经获得的信息。以下条件同时成立才主动询问：

1. 至少有两项有实质工作量、可分别验收的子任务，并且存在能够独立推进的工作。
2. 各部分的能力需求不同，或独立复核明显有价值；收益足以覆盖上下文整理和整合成本。
3. 当前会话有适合的原生子代理能力；任务没有禁止委派，且本任务尚未拒绝或正在等待同一建议的回答。

简单提取、短问答、一个不可拆的证明、同一核心文件的紧耦合修改通常不询问。不要为了满足条件人为制造子任务。用户主动要求评估时，可直接说明适合或不适合及一个具体理由，不需要因此启动调度。

## 一次建议，等待明确回答

使用可用的用户输入工具，提出简短选择：

“这项任务的〔具体部分 A〕与〔具体部分 B〕可以独立推进，且适合不同模型。是否启用智能任务调度，按子任务分配模型和推理等级并执行？”

选项为“启用本次调度”和“按当前方式继续”。若用户输入工具不允许处理这种启用确认，改用简短普通提问，遵守当前沟通规则。

- 无回答、超时或预选项不等于同意。仍按既有授权推进不依赖该决定的工作；不要因建议挂起而阻塞整个任务，也不重复追问。
- 用户同意：读取同插件的[执行技能](../route-task/SKILL.md)，说明本次启用并继续；计划模式或“只分析”的限制仍然有效。
- 用户拒绝或要求继续原方式：当前任务不再建议，继续原任务；后续明确要求启用可覆盖此前拒绝。
- 用户已明确调用插件或执行技能：无需再建议，直接交给执行入口。

同意、拒绝与待回答状态跟随当前任务上下文及必要的续接摘要保存，不写跨任务记忆，不创建后台监控。自动发现由 Codex 决定，本入口不保证每一个复杂任务都弹出建议。
